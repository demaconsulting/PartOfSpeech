# Staged Corpus Corrections

License: CC0-1.0

Label corrections for the open corpus, MASC and the silver data that follow the conventions of
[CONVENTIONS.md](../CONVENTIONS.md), staged as small tables instead of edits of the corpus files. **Nothing in this folder
has been applied yet:** the corpora under `open/`, `masc/` and `silver/` are exactly the importer output, and a later change
applies the rows and regenerates everything that depends on the labels (the lexicon, the weights, the evaluation record).

The rows are labels and addresses of tokens: the labels and the selection are dedicated under CC0-1.0, like the corpus labels.
Token forms of MASC rows and the short context excerpts in `candidates.tsv` are MASC text, which stays under its own license
(see `masc/ATTRIBUTION.md`).

## Contents

| File | Kind | What |
| --- | --- | --- |
| `mechanical.tsv` | corrections | 2,048 rows from the mechanical rules (tier `fix`): the rule knows the correct tag |
| `candidates.tsv` | candidates | 12,490 cases that need judgment (13,067 tokens in 9,287 sentences), never changes |
| `exceptions.tsv` | exceptions | reviewed cases that stay as they are; empty (header only) until the adjudication |

`llm.tsv` (same format as `mechanical.tsv`) is where the adjudication of the candidates will put its rows. Everything is
generated by `tools/data/make_corrections.py`; do not edit the tables by hand.

## Format

All files: UTF-8 without BOM, LF, NFC, final newline. A table starts with comment lines (`# corpus`, `# license`, `# kind`,
`# columns`, `# generator`, and one `# input = <file> sha256 <hash>` line per corpus file the rows were derived from), then one
row per line, tab separated, sorted by the key below. The `# columns = ...` line is the column list of the C# data tests.

### Corrections (`mechanical.tsv`, `llm.tsv`)

```text
source  split  source_id  sent_id  token_index  token  old_tag  new_tag  old_status  new_status  provenance
```

| Column | Value |
| --- | --- |
| `source` | `open`, `masc` or `silver` |
| `split` | `train`, `dev` or `test` for `open`; `-` for `masc` and `silver` |
| `source_id` | the document id of the sentence (`# source_id`), checked against the corpus |
| `sent_id` | `# sent_id` of the sentence |
| `token_index` | 0-based position among the token rows of the sentence |
| `token` | the form, checked against the corpus |
| `old_tag`, `new_tag` | UPOS tags; never `_` (masked silver rows are not addressable) |
| `old_status`, `new_status` | the whole status cell (`unchecked`, `disputed+mentioned`), valid by `common.parse_status` |
| `provenance` | `rule:<id>` (a rule of the catalog below) or `llm:<model>:<run>` |

A row is valid on its own when the source and split are a legal pair, the index is a number without leading zeros, the tags are
tags, the old and the new value differ, the base status changes at most to `disputed` and only for an `llm:` row (`ptb`,
`silver` and `masked` are never new bases), and a `rule:` row keeps its status cell. The tags and flags of the corpus file are
the only things a row changes; `source_tag` and every other column stay as they are. The key
`(source, split, sent_id, token_index)` is unique across all correction tables: a second row for the same token is a duplicate
(same change) or a conflict (different change). Order: `source`, `split`, `sent_id` by UTF-8 bytes, `token_index` numerically.

### Candidates (`candidates.tsv`)

```text
source  split  source_id  sent_id  token_index  span_length  token  current_tag  current_status  source_tag  candidate_rule  hint  context
```

One row per token and candidate rule, sorted by the key and the rule. `span_length` is 1, or the number of tokens of a
mentioned phrase that starts at `token_index`. `source_tag` is the Penn tag (MASC), the model class and probability (silver) or
empty (open). `hint` is machine evidence (`penn=VBG; head=modes`, `degree-before=very`, `quote=" "`), `context` the sentence
window of six tokens either side with the target in brackets. A violation of a `check` rule is a candidate under the id of its
rule (hint `check-rule`), so every violation the linter reports has a row for the adjudication. A token that has a correction row
is never a candidate. The tag columns describe the corpus before the corrections; they are history once the corrections are
applied.

### Exceptions (`exceptions.tsv`)

```text
source  split  source_id  sent_id  token_index  token  rule  reason  provenance
```

A reviewed decision "keep as is" for one token and one rule id of the catalog. The linter drops the matching violation and the
generator leaves the token out of the candidates.

## States and Apply

A corrections table is valid against the corpora in one of two states: every row matches the corpus in the **pending** state
(token, `old_tag`, `old_status`) or every row matches in the **applied** state (`new_tag`, `new_status`). Rows of both states
are an error (`mixed-state`). So the same files stay valid after the rows are applied, and a partial application is caught.

`python tools/data/corrections.py apply` prints what would change (a dry run); `--write` edits the corpus files in place, line
by line, so that comment lines such as `# genre = ...` and every other column survive, and the header gains the line `# status
flags = ...` when the first flag appears. `apply --write --reverse` restores the files byte for byte. A table that does not match
is refused. Applying is exercised only on test fixtures and on in-memory copies of the committed corpora until the corrections
are merged. `make_corrections.py --check` regenerates the tables and compares them with the committed files; it is meaningful only
in the pending state, because the tables describe the corpora before the application.

## Commands

```text
python tools/data/corrections.py validate                  # every table against the corpora (exit code 1 on an error)
python tools/data/corrections.py show --rule out-of        # rows in context
python tools/data/corrections.py apply [--write] [--reverse]
python tools/data/make_corrections.py                      # regenerate the three tables
python tools/data/make_corrections.py --check              # compare with the committed tables
python tools/data/make_corrections.py sample --n 50 --seed 20261108 [--per-rule 4] [--only RULE,RULE] [--out FILE]
python tools/data/make_corrections.py fixed-point          # apply in memory, then the rules must find nothing left to fix
python tools/data/make_corrections.py catalog              # the rule tables below
python tools/data/check_conventions.py [--apply] [--enforce] [--list RULE] [--tsv FILE]   # the linter
```

The linter reports per rule and source how many violations are left; `--apply` lints the corpora as they are after the staged
corrections, and `--enforce` fails while any violation is left (the evaluation-only STE set is shown but never counts). After the
rows are applied, no mechanical (`fix`) rule finds anything: `make_corrections.py fixed-point` and the committed-data tests prove
it, with the corpus resources recomputed from the corrected data.

## Rule Catalog

Every rule has an id (the `rule:<id>` of its rows), a section of CONVENTIONS.md and a tier. **Mechanical** (`fix`) rules know
the tag and write a row per token; a token has at most one row (a conflict between two rules is an error, solved by a guard).
**Check** rules report a convention violation that needs a decision; the linter lists them, the adjudication resolves them, and
the final check demands zero. For MASC the Penn tag (`source_tag`) is used where it disambiguates (`get`-passive needs `VBN`);
the importer is not changed, and a different Penn-to-UPOS mapping would be expressed as rows. Silver model classes are never a
reason to override a rule.

| Id | Tier | CONVENTIONS section | Detection and change |
| --- | --- | --- | --- |
| `multiword-prep` | mechanical | Multiword Prepositions | `due to`, `prior to`, `such as` ADJ ADP; `instead of`, `next to`, `rather than` ADV ADP; `because of`, `along with` ADP ADP; `thanks to` NOUN ADP; the last word is ADP (SCONJ before a clause is kept); not `due to` + infinitive, not the phrasal `come along with` |
| `according-to` | mechanical | Multiword Prepositions | `according to`: both words ADP (`according` is not VERB or ADJ) |
| `out-of` | mechanical | Multiword Prepositions | `out of` ADP ADP after a noun phrase, an adverb or a form of `be` (not a phrasal verb such as `get out of`, not `run out of`) |
| `at-least` | mechanical | Degree and Quantity Words | `at least`, `at most`: ADP ADJ |
| `more-than` | mechanical | Degree and Quantity Words | `more than`, `less than` before a quantity (number, `a`/`an`/`half`, `one`): `more`/`less` ADJ and `than` ADP; not `any more than`, not a clause (`more than a cloud is`) |
| `a-little` | mechanical | Degree and Quantity Words | `a little`: DET ADJ (`little` is never ADV, PRON or NOUN after `a`) |
| `partitive-det` | mechanical | Degree and Quantity Words | `all, any, both, each, either, some` before `of`: DET (never PRON or ADV); not `at all of` |

| `partitive-noun` | mechanical | Degree and Quantity Words | `plenty of`, `lots of`: NOUN |
| `one-of` | mechanical | Numbers and Dates | `one of` + noun phrase or pronoun: `one` NUM (not after `the`, `which`, `any`, ...) |
| `half-noun` | mechanical | Degree and Quantity Words | `half of`: `half` NOUN |

| `correlative-the` | mechanical | Degree and Quantity Words | `the more you wait, the harder it gets`, `the bigger, the better`: both `the` ADV |
| `decade` | mechanical | Numbers and Dates | a decade (`1990s`, `'90s`, `mid-1800s`) is a NOUN (not `13s`) |
| `regnal-numeral` | mechanical | Numbers and Dates | a Roman numeral of two or more letters directly after a name: NUM (`Henry II`, `World War II`) |
| `big-number` | mechanical | Numbers and Dates | `million`, `billion`, `trillion`, `thousand` after a number: NUM; `some` before a number: DET |
| `as-possible` | mechanical | Multiword Prepositions | `as X as possible`: the second `as` SCONJ |
| `for-subject-to` | mechanical | Multiword Prepositions | `for` + subject + `to` + verb after an adjective, `too`/`enough`/`so`, `way`/`time`/`place`/`room` or a verb of waiting, asking, calling, hoping, arranging: `for` SCONJ; not after a subject noun that takes its own infinitive (`the right to marry`) |

| `clock-suffix` | mechanical | Names and Labels | `a.m.`, `p.m.`, `am`, `pm` after a clock numeral of 1 to 12: NOUN |
| `do-your-best` | mechanical | Degree and Quantity Words | `do your best`, `all the best`: `best` ADJ (a superlative that stands for a noun) |

| `modal-aux` | mechanical | Annotation Conventions | a modal tagged VERB before a verb, `not` or an adverb: AUX (the stem of `can not`) |
| `possessive-det` | mechanical | Annotation Conventions | `my, your, his, its, our, their, whose` directly before a noun, adjective or number: DET; `her` the same after a preposition, conjunction or punctuation (before a noun, number, or `own`) |
| `be-participle-adj-not-gradable` | check | Prenominal Modifiers and Predicate Participles | agentless `be` + a participle tagged ADJ without a degree word that is not known to be gradable: passive VERB or gradable ADJ? |
| `be-passive-agent` | check | Prenominal Modifiers and Predicate Participles | `be` or a linking verb + a participle tagged ADJ with an overt `by`/`from` agent: VERB unless the participle is gradable (`fascinated by` ADJ, `dominated by` VERB) |
| `be-aux-passive` | check | Prenominal Modifiers and Predicate Participles | `be` tagged VERB before a participle tagged VERB: AUX when the participle is a passive, or the participle is a gradable ADJ |
| `get-state-participle` | check | The get-passive | `get` + a state participle (`get used to`) tagged AUX + VERB instead of VERB + ADJ (no case yet) |
| `out-of-phrasal` | check | Multiword Prepositions | `run out of`: `out` is a phrasal-verb particle (ADV), not ADP |
| `infinitive-to` | check | Annotation Conventions | `to` is PART only as the infinitive marker: not ADP before a bare verb, not PART before a noun |
| `modal-aux-other` | check | Annotation Conventions | a modal tagged ADV, PART, ADJ, ADP, SCONJ or X before a verb; `ca`, `wo`, `sha` before `n't` not AUX (no case yet) |
| `speaker-label` | check | Numbers and Dates | `A:` and `B:` at the start of a sentence label a speaker: PROPN (no case yet) |
| `no-all-degree` | check | Annotation Conventions | `no`/`all` directly before an adjective or adverb (`no better`, `all alone`) is ADV, not DET |
| `language-name-token` | check | Names and Labels | a language name is PROPN, ADJ or NOUN, never ADV, VERB or X (no case yet) |

The three participle rules that were demoted by the precision gate (`be-passive-verbal`, folded into
`be-participle-adj-not-gradable`; `be-passive-agent`; `be-aux-passive`) stay visible to the linter. The reason is the
convention itself: a participle after `be` is a passive unless it is gradable (test 2 before test 4), and gradability is a
property of the meaning that the corpora show only for forms that happen to occur after `very`. The tested wrong calls were
`focused on`, `fascinated by`, `well established`, `far removed`, `composed`, `was lost`, `was stuck`, `are gone` and `be done`,
all states that look like passives.

## Precision Record

A mechanical rule may stay mechanical only if a hand check finds it at least 97 percent correct. The check is a recorded
procedure, not a test: `make_corrections.py sample` draws rows with ten tokens of tagged context either side; the implementer
(an automated agent, one rater) reads every row against CONVENTIONS.md and records the verdict with its reason in a scratch file
(not committed). A wrong row means the rule is tightened with a guard or demoted to `check`/candidates, the tables are
regenerated and a **fresh** sample is drawn. Because 50 random rows undersample small rules, every round adds a stratified
supplement (`--per-rule`, all rows of a rule with fewer rows), and the two participle rules with fewer than 20 rows were read in
full.

| Round | Rule set | Random sample (seed, rows, wrong) | Stratified sample (seed, per rule, rows, wrong) | Result |
| --- | --- | --- | --- | --- |
| 1 | first version, with participle rules `be-passive-verbal`, `be-passive-agent`, `be-aux-passive` | 20261104, 50, 8 (84 percent) | 20261105, 4, 126, 8 | failed |
| 2 | participle rules demoted to `check`, guards added | 20261106, 50, 1 | 20261107, 4, 113, 2; census of `be-copula-gradable` and `link-participle`, 35 rows, 8 wrong | failed |
| 3 | final | 20261108, 50, **0** | 20261109, 5 for 12 rules (the five changed ones and seven large ones), 53 rows, **0**; census of the two participle rules, 25 rows, **0** | passed |

Round 1: seven of the eight random errors were `be-passive-verbal` (a state read as a passive: `settled`, `focused`, `composed`,
`lost`, `well established`, `gone`, `done`) and one `be-passive-agent` (`far removed from`). In the stratified sample
`be-aux-passive` had two wrong rows, `be-passive-agent` and `be-passive-verbal` one each, `be-copula-gradable` (`somewhat
amended`), `half-adv` (`by half to ...`), `more-than` (`any more than a cloud is`) and `possessive-det` (`with her last Tuesday`)
one each. The three participle rules were demoted to `check`; the others got guards.

Round 2: one random error (`is particularly seen`: a focusing adverb is not a degree word), two stratified errors (`most
reserved for`, and `what they felt belonged to them` read as a linking verb), and in the participle census `increasingly
emphasised`, `particularly seen`, `most reserved`, `felt belonged` and `seem to read`. The fixes: `most`, `least`,
`particularly`, `especially`, `increasingly` and the adverbs that grade verbs too (`somewhat`, `completely`, `well`, `far`, ...)
do not make a participle gradable; `felt` is not a linking verb; an infinitive `to` breaks the chain between `be` and the
participle.

Final result for the rules as committed (distinct rows of rounds 2 and 3 that the final rule set still produces, plus the
censuses): **261 rows, 0 wrong, 100 percent** (a zero in 261 rows bounds the error rate below about 1.2 percent at 95 percent
confidence). Round 3 alone: 103 random and stratified rows, 0 wrong (lower bound about 97 percent).

- **Adjudication.** Read `candidates.tsv`, decide each case from the row (tag from scratch, never by anchoring on the current
  tag), write the decisions as rows to `llm.tsv` (`provenance` `llm:<model>:<run>`; flags such as `unanimous+mentioned` by
  changing `new_status`, a genuinely unsettled case to `disputed`) and the "keep as is" decisions to `exceptions.tsv`. A token
  can have one correction row only; a candidate never repeats a token that has a mechanical row, so a decision for such a token
  replaces its mechanical row (and the mechanical rule is then restricted by a guard or the row is removed by the generator).
- **Applying.** `corrections.py validate`, then `apply --write`, then regenerate the lexicon, retrain and record the evaluation
  (`train --check`, the lexicon check and the evaluation record pin the corpus files). The linter then runs with `--enforce`.
- **Evaluation data.** The development and test splits of the open corpus are corrected like the training split; the evaluation
  record pins their SHA-256, so the change that applies the rows must also reissue those pins.
